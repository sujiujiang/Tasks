# ❤️我的GitHub学习笔记

## 1️⃣对于Geek的理解
&emsp;&emsp;Geek翻译作极客，指的是一群热爱技术、喜欢探索未知、喜欢动手实践的人。
根据我和mentor的沟通，和朋友的交流以及自己对于Geek的一个理解，我觉得Geek精神就是
1. 充满好奇心：对于未知事物，善于动用一切可利用的工具为我们所用去解决问题
2. 动手搭建：遇到问题不是直接等现成答案，而是愿意自己折腾、调试、反复尝试，在踩坑里面学习
3. 记录学习：不惧试错踩坑，乐于把坑标记、把过坑方法记录
4. 乐于分享：愿意将所学所知所思所想和伙伴分享

## 3️⃣打开GitHub
&emsp;&emsp;其实刚开始我打开的很顺畅，只是开久了长期没操作，以为被踢出服务器了重连就好了，还没有担心这个问题。
实际上我错了，这个问题成为了我推进考核第二大难点！

&emsp;&emsp;于是我和朋友先讨论了如何解决这个问题，其中我们了解到这个GitHub的服务器远在海外，跨越遥远的海面传输网络，在国内的我们自然就是容易拥堵、丢包，任何浏览器里的网页开始转圈圈。这时我就在网络中搜索打不开怎么办，不过搜到的大多是为了使下载更快的镜像网站，并不符合我们目前的学习需求；于是乎我就转战到了豆包，豆包给出了换DNS、换浏览器和镜像网站的方案，实践后发现怎还是如此缓慢！！

&emsp;&emsp;之后我就带着已有成果来问我的mentor，也是狠狠提醒我还有别的搜索渠道呀，我们的小豆包或许难以切合地处理我的问题。洗完一个澡回来后，发现更换成热点然后换了一个DNS好多了，但我还是去到了小红书一边搜索美化教程一边逛如何更通畅的链接，于是搜索到了这个Watt Toolkit加速器（这不是我舍友用来加速steam用的吗，这期在GitHub上居然免费了）。用上之后也是美美进入了GitHub，目前还没有断连的情况。

## 4️⃣一个整洁的文档
根据我“多年”美化文档、ppt还有对于新学markdown语法规范来看，我觉得我的这份文档还算是整洁规范的，因为有这些特征、遵守了这些规范：
&emsp;&emsp;第一，使用了多级标题搭建文档框架，用不同等级标题区分大主题和小要点，结构清晰一目了然；
&emsp;&emsp;第二，段落之间空行，段落开头会使用缩进，看起来没有那么密集眼花；
&emsp;&emsp;第三，并列内容使用列表排版，重点内容适当加粗；
&emsp;&emsp;第四，使用了一些表情符号使得文档更可读美观。
